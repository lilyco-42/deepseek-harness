## 北极星

用户在网页或手机用网站模型聊天；搜索、URL、网站 GitHub OAuth 和确认后的附件都要把真实资料交给同一轮模型并生成可核验回答。数据按账户隔离；A7A 私有；个人设备离线不能影响普通流程。DSH 是目标唯一对话与工具循环，New API 是模型网关。

### P0 放行条件

- 上表全部项目均有可复查的 Actions 和浏览器证据；OAuth 需测试授权连接、读取资料、模型回答和撤销。
- New API 模型用量、用户积分和 DSH 事件可用同一业务 requestId 对账；不双扣费、不重复执行工具。
- 在通过双账号隔离前，DSH 入口只对测试账号开放；不得加载共享管理员主机能力、任意插件或全局 shell。
- P0 未过时维持当前线上入口。代码与构建通过不等于已部署；部署也不等于已验收。

## P3：先不进入本轮

自动代发 QQ/微信/Telegram、公开算力出租、多个 coding worker 委派、重量级 LLVM/WASM 编译器包。只有明确用户需求、资源收益和隔离证据后才新开设计。

## 固定规则

- 所有仓库的构建、测试、平台打包走 GitHub Actions；不在本地运行项目构建或测试。
- 使用独立测试账号和合成数据；不把真实私密邮件、仓库资料或令牌用作演示。
- 不使用或重启站点所有者的 Radxa A7A 来代替通用设备测试。
- Search、URL、OAuth、附件都必须证明实际输入到达当前 DSH 模型轮；工具执行日志不能替代回答。
- OAuth 和本机 gh 是两套独立授权；模型永远不接触凭据。
- 每次变更记录 commit、Actions run、部署版本和浏览器结果；不得把“尚未部署”写成“线上已修复”。
