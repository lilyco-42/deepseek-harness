# Lain42 全平台 Agent：目标与执行计划

状态：活动 Goal 的当前执行版，修订于 2026-09-27。任务顺序见[执行看板](./lain42-agent-task-board-2026-09-27.md)，架构边界见[平台架构建议](../architecture/architecture-recommendation-lain42-platform.md)。本文区分已有证据与未完成能力，不代表线上功能已经完成。

## 一句话目标

让用户打开网页或手机就能用 Lain42 网站模型聊天、检索资料并分析自己选择的文件；需要运行 CLI 时再连接本人授权的设备。DSH 负责唯一的对话与工具循环，New API 保留为模型网关，账户、授权、额度和数据所有权由 Lain42 管理；客户端承担适合本地运行的计算。

## 用户结果与边界

1. **打开即用**：响应式 Web/PWA 默认接网站模型；匿名用户可受限试用，登录后保留跨设备历史和权益。
2. **工具真的完成任务**：搜索、公开 URL、GitHub OAuth 和用户确认的附件进入同一轮模型，最终回答问题并给出来源；工具成功通知本身不算答案。
3. **凭据和数据隔离**：网站 GitHub OAuth 与设备上的 gh 独立；会话、凭据、文件、设备、知识对象、用量按账户隔离，模型上下文和日志不含令牌。
4. **设备按需连接**：普通聊天、公开搜索及网站 OAuth 查询不依赖个人设备。CLI/MCP 只在用户明确选择的本人设备上执行。站点所有者的 Radxa A7A 永远是私人设备，不是共享后端。
5. **客户端优先做合适的计算**：浏览器 JS/Worker/WASM 做预览、解析和展示；WASM 不绕过 CORS、不能直接运行系统 CLI，也不能自动访问用户磁盘或 Cookie。
6. **可以运营**：积分统一记账，管理员发放可审计；普通用户私有知识空间 5 GB，会员 20 GB，由服务端强制配额。

## 架构决定

- **一个用户界面、一个会话真值、一个对话控制者**：Web/PWA 是产品入口；DSH 是唯一对话、上下文和工具循环；New API 是模型路由与用量入口；Lain42 是账户、授权、额度、账本和数据所有权的真值。
- **渐进迁移**：先在受保护的新入口接入 DSH；未完成租户隔离和真实流程验收前，线上默认入口仍保留可回滚路径。不在新旧系统同时推理、双扣费或重复执行工具。
- **按任务选执行位置**：公开网页若浏览器允许跨域且用户选择客户端路径，可由客户端读取；其他来源走明确受限的搜索/WebFetch 适配器。私有 GitHub 通过网站 OAuth 适配器。CLI/MCP 仅在本人设备。
- **可替换而不过度拆服务**：MCP/CLI/ACP 是工具适配协议，不是账户权限协议；先保持必要的服务边界，按并发和资源测量再决定拆分。ZeroStack 是后续可选 coding worker，不进入首发聊天循环。
- **不做大重写**：代码高亮用客户端现有组件按需注册语言；文件解析用 JS/Worker，只有性能证据支持时才引入 WASM。Tauri 以后复用同一网页体验。

具体服务边界、数据流和迁移图见[架构建议](../architecture/architecture-recommendation-lain42-platform.md)。

## 唯一近期目标：P0 放行门

当前不是继续添加外围功能，而是让 DSH 的受保护测试入口完成下面的闭环，再决定是否切换默认入口：

1. **身份到 DSH 的安全映射**：用户身份必须从 New API 已验证会话推导；不能相信浏览器传来的 userId/workspaceId。服务间调用使用短时、限定受众与权限的身份凭证。每个 DSH 会话、事件、工具调用和存储对象均可追溯到其所有者。
2. **网站模型的真实多轮对话**：由 DSH 发起模型请求；问候、常识、短追问、纠正、工具失败后的新问题都回答当前问题。DeepSeek 这类名称不能被宽泛关键词规则误路由成搜索工具。
3. **真实工具闭环**：搜索、公开 URL 和网站 GitHub OAuth 的实际结果回到同一轮 DSH；模型继续推理并给出可打开来源。OAuth 错误说明重连/权限/限流等实际原因，不甩给用户本机 gh 登录。
4. **附件闭环**：文件只由用户选择；客户端展示将发送的解析范围，用户确认后才交给模型。答案要能引用合成测试文件中的真实内容；取消、超限、失败和重连不应误发或重复扣费。
5. **完整账户隔离**：两个测试账号互相不能读取会话、OAuth、附件、设备、知识对象或用量；撤销授权后失效。无设备在线时，聊天、搜索和网站 OAuth 仍然成功。
6. **发布证明**：相应 Actions 行为回归通过，并在真实浏览器完成上述流程。CI 通过是必要条件，不替代真实端到端证据；完成前不切默认入口、不部署未验收的切换。

### 建议的产品服务契约（实施前与现有代码对齐）

这些是边界要求，不预设当前已有相同 URL：

- 浏览器只调用 Lain42 的已认证会话接口；每次写请求含幂等 requestId。服务端由登录态确定 userId/workspaceId。
- Lain42 到 DSH 的内部调用应携带短时签名的主体、会话范围、允许能力、过期时间和关联 requestId。DSH 校验签名与受众；不能接受浏览器提供的内部主体声明。
- 网站入口只暴露明确挑选过的 web-safe DSH 能力；不能把 DSH Host 的任意 cwd、workspace、服务端文件、原生打开路径、shell 或管理员插件面直接转发给浏览器。设备目录能力只能由本人设备适配器提供。
- 会话/轮次/工具调用共享稳定 ID 和有序事件号。前端只渲染状态；工具失败、超时、拒绝授权都变成该轮可解释结果，不能崩溃后把失败消息污染下一轮。
- OAuth 令牌只留在加密凭据层；GitHub 适配器按当前主体取凭据。模型仅接收用户允许的仓库资料，不接收令牌。
- 文件默认留在客户端；用户确认附加才发送本轮所需内容。Pin 才创建服务端持久对象，OSS 对象为私有且由服务端做配额校验。
- 执行位置和所需权限随工具声明；搜索/读取不得默默切换成本地 gh，CLI 也不得默默运行在网站服务器或站点所有者的 A7A。

## 任务依赖与阶段

1. **P0-1：定义并验证 DSH 接入契约与隔离边界。**盘点现有 New API 会话认证、DSH SessionController、模型入口和事件流；设计受保护的新路由与回滚点；先加入服务主体、所有权和事件契约测试。
2. **P0-2：把 DSH 作为唯一对话循环接到网站模型。**复用 Lain42 登录和额度，DSH 持有上下文和工具循环；先用专用测试账号开隐藏入口，验证流式事件、会话续接、失败状态及请求幂等。
3. **P0-3：多轮对话与错误恢复。**覆盖问候、DeepSeek 常识问题、短追问、纠正、模型限流、服务端容量和工具失败。只对无副作用且尚未输出的请求有限重试。
4. **P0-4：搜索、WebFetch、GitHub OAuth 到模型回答。**逐一验证实际输入、结果来源、工具后续模型回答；包含 OAuth 断开/撤销和 401/403/429 安全提示。
5. **P0-5：附件分析闭环。**用合成附件验证预览范围、显式确认、客户端解析、模型引用内容、取消、限制、网络失败和重试。
6. **P0-6：双账号和设备离线门禁。**扩展已有 OAuth 凭据隔离测试，覆盖会话、文件、设备、知识与用量；关闭个人设备后重跑普通产品流程。
7. **P0-7：发布门。**Actions 通过、真实浏览器三条流程通过、隔离矩阵通过后，才按测试账号分阶段切换 DSH；任何阶段保留单回合唯一执行者和回滚路径。
8. **P1：本人设备、积分账本、移动与代码体验。**设备写入审批/撤销、CLI/MCP 所有权；充值/赠送/预留/扣费/退款的统一幂等账本；手机完成输入、附件、取消、重连；Rust/JSON/Markdown 客户端高亮和复制。
9. **P2：私有知识空间与桌面入口。**5/20 GB 私有 Pin、并发配额、版本删除；Tauri 复用 Web；邮件等连接器先做只读/草稿，发送另行授权。
10. **P3：有需求证据后再做。**自动代发消息、公开设备出租、多 Agent/ZeroStack 委派、重量级编译器下载包。

## 不纳入当前放行门

- 不把 A7A 当作公共后端，不要求用户绑定站点所有者设备。
- 不把“连接 OAuth”卡片、工具调用成功提示、单轮真实回答、框架已有能力或 CI 绿色当作整个功能完成。
- 不以 Rust/WASM 或 ZeroStack 重写替代产品闭环；WASM 不绕过同源策略，也不执行系统 CLI。
- 不让 GitHub OAuth 仓库读取依赖本机 gh 登录。
- 不在旧新系统同时执行推理、扣费或有副作用工具；不在未通过 P0 前把新入口切为默认。
- 不把用户选择的附件静默存成知识库，也不把模型网关渠道余额当作 Lain42 用户积分。

## 固定工程约束

- 项目构建、测试与平台打包只在 GitHub Actions；本地不运行项目构建/测试。
- Actions 未通过不部署；Actions 通过但浏览器验收未通过也不宣布产品完成。
- 手工联调使用专用测试账号、合成资料和最低必要权限；任何日志不得记录 OAuth token、API key 或私有文件全文。
- 设备接入必须可见所有者、目标设备、路径/权限、写操作确认、撤销和断线状态。
- 每项“完成”同时记录代码版本、Actions run、测试账号/浏览器流程、结果和限制。
