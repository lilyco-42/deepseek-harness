# Lain42 全平台 Agent：目标重排（2026-09-27）

本文件保留较早执行顺序和历史证据。当前活动目标、阶段与验收以[Goal 重规划](plan/goal-replan-lain42-2026-09-27.md)和[机器计划](plan/goal-replan-lain42-2026-09-27.json)为准；架构边界见[平台架构建议](architecture/architecture-recommendation-lain42-platform.md)。旧计划不再作为 DSH 优先迁移指令。

## 目标合约

把 Lain42 做成打开网页或手机就能用的全平台 Agent：默认通过 New API 使用网站模型；普通聊天不依赖设备；用户需要搜索、读网页、查看本人 GitHub 或分析附件时，Agent 必须先取得真实资料，再基于资料回答并展示来源。网站账号、OAuth 凭据、会话、文件、设备、知识空间、积分与用量彼此隔离。客户端用 JS、Worker 或经验证有收益的 WASM 承担代码呈现和本地文件/二进制解析；只有用户主动授权后，CLI/MCP 才能在用户自己的设备执行。产品最终支持受限免登录试用、统一可审计积分，以及普通用户 5 GB / 会员 20 GB 的私有知识空间。

六项必需能力与验收边界：

1. **打开即用**：浏览器、PWA、手机共用同一套聊天与登录；免登录试用有服务端限额，不获得个人凭据、持久私有文件或设备权限。
2. **真实资料闭环**：搜索、公开 URL、GitHub OAuth 和用户确认的附件结果必须进入当前 turn 的模型上下文，最终回答要针对问题并带可打开来源；工具调用成功本身不算完成。
3. **账号连接与隔离**：网站 GitHub OAuth 与设备上的 `gh` 分开授权；撤销立即生效；令牌不进入模型或日志；账号之间不能读取彼此历史、文件、凭据、设备、知识和用量。
4. **本人设备按需执行**：仅在用户明确选择后连接其本人设备并运行 CLI/MCP；站点所有者的 Radxa A7A 永远是私人设备。设备离线不得影响网页聊天、模型、搜索或 OAuth。
5. **客户端解析和呈现**：代码高亮、文件预览、文档及二进制的有界本地解析优先在客户端完成；用户看到并确认实际发送内容。JS/Worker/WASM 按能力与实测选择，不能假设 WASM 可绕过浏览器跨域或权限限制。
6. **可运营权益**：统一积分账本支持充值/消费/退款/管理员发放和审计；模型用量可对账；Pin 知识库由服务端强制普通用户 5 GB、会员 20 GB 配额，并正确处理并发、删除和回收。

**完成定义**：常用路径在真实浏览器和手机视口跑通；真实模型回答与工具资料可按同一 turn 追踪；双账号隔离、设备离线独立、失败恢复和费用幂等通过 GitHub Actions；手动浏览器证据和回滚办法齐全。未达到这些条件，不切换默认线上入口，也不宣称商业化或功能完成。

## 北极星

用户打开网页或手机，就能用网站模型完成连贯对话；搜索、公开 URL、GitHub OAuth 和用户确认的附件都能把真实资料交给模型，得到针对当前问题且有来源的回答。会话、凭据、文件、设备、知识空间和用量按账号隔离。CLI 只在用户明确选择的本人设备运行；站点所有者的 Radxa A7A 永远是私人设备，普通聊天不依赖配对设备。浏览器承担适合本地执行的解析与代码展示，网站负责身份、会话协调、模型接入和商业账本。

DSH 是目标对话与工具循环，New API 保留现有网站身份、授权和模型网关能力；只有身份边界和真实闭环通过验证后，才逐步切换线上入口。客户端优先不等于强行 WASM 化：按需使用 JS、Worker 或 WASM，不能绕过 CORS、用户权限或操作系统隔离。

## 执行规则

- 构建、自动化测试和平台打包只在 GitHub Actions；不在本机运行项目构建或测试。
- 先用受保护测试入口和合成账号验证。双账号隔离、端到端用户流程及回滚证据齐全前，不把 DSH 切成默认线上 Agent。
- 不接入 ZeroStack、重型 LLVM/WASM、自动代发消息或额外微服务来替代核心闭环。
- 不使用、重启或共享 A7A；浏览器 OAuth 与用户设备上的 gh 登录互相独立。
- 每项完成必须有代码版本、Actions 结果和真实浏览器流程证据；“组件已接入”“工具完成通知”或“CI 通过”都不能代替模型最终回答。

## 新阶段与放行条件

### G0：恢复可信的普通对话
定位当前线上容量拒绝、推理连接失败、服务 503 和不相关回答，分清基础设施故障、模型响应、旧上下文污染和前端展示。普通问答必须真实调用配置模型；失败时展示可操作错误，不用硬编码答案伪装成功。

验收：问候、常识、含糊短消息、纠正上一轮和 DeepSeek 常识测试都围绕当前输入；失败回合不污染下一轮；设备离线时普通聊天仍可用。Actions 回归通过，并能关联真实模型请求。

**当前进展（未完成 G0）**：线上公开状态端点健康，版本为 `agent-4f9032e`。已确认历史 `system disk overloaded (96.2%, threshold 95%)` 是站点资源阈值拒绝，不是模型限流，也不依赖 A7A。New API 前端此前把一般 503 归因为模型/渠道故障；已在提交 `11b65a2` 增加站点资源过载专用提示和回归用例，GitHub Actions CI `36276903522` 与 Linux Agent 构建包 `36276903498` 均通过。此修复尚未部署，且不会释放服务器磁盘空间；服务器容量恢复、真实浏览器普通聊天及设备离线验收仍未完成。

### G1：建立安全的 DSH 网站入口
浏览器只使用现有网站登录态。New API 服务端从认证会话推导用户身份，以短时、限定受众和能力的凭证调用 DSH；DSH 不信任客户端提交的 userId、workspaceId 或 cwd。网站只暴露 web-safe 会话、模型和工具循环，不暴露 DSH 主机文件、任意路径、shell、管理面或任意插件安装。

验收：双测试账号不能跨读会话、OAuth、文件、设备、知识或用量；伪造身份、跨账号 sessionId、重复 turn 和迟到事件都被拒绝或安全去重。先只对测试账号开放。

**已核实的 DSH 边界**：`PeerScope` 文档明确表示它只记录连接方及生命周期，不承载账号身份/授权；`HostConnectionService` 将通过浏览器进程认证的请求统一作为一个 operator peer；`session.create` 接受 `sessionId`、`workspaceId`、`cwd`；标准 Web 预设含终端与文件系统工具。当前 New API Agent 的搜索/网页读取工具循环运行在浏览器端，尚未接入 DSH。因此不能把 DSH 通用 `/api` 反向代理给网站，也不能只靠不可猜 session id 宣称隔离。实现必须新增专用内部站点入口：由 New API `UserAuth` 推导主体，签发短时服务端断言；New API 保存并校验账号到不透明对话键的归属；DSH 从已验证主体和对话键派生会话身份，固定工作区并强制无 shell/宿主文件/插件管理的站点预设。只有该入口可触达 DSH 会话与流，公共浏览器不能访问 DSH 进程认证接口。

### G2：打通“提问 → 工具 → 模型回答”
先让 DSH 经 New API 完成多轮模型对话，再逐项闭环搜索、公开 URL、GitHub OAuth：真实资料进入同一轮模型，模型继续推理并输出回答与可打开来源。GitHub OAuth 与本机 gh 独立；令牌不能进入模型上下文或日志。客户端网页读取仅在 CORS 允许且用户选择时发生，否则走明确受限的 WebFetch 路径或说明限制。429、5xx、离线、拒权和工具错误显示实际状态，不把工具完成通知当答案。

验收：每条流程都能对应同一个 turnId 下的模型请求、工具输入/输出和最终回答；来源可打开；OAuth 撤销后立即失效；重连不重复扣费或执行副作用。

### G3：完成客户端附件与代码体验
浏览器先预览和解析文件，展示实际将发给模型的范围并等待用户确认；代码 Markdown 在客户端按需加载高亮与语言标识，长代码块不阻塞输入。只有用户 Pin 时才进入持久知识空间。

验收：合成文件内容经用户确认后可被模型准确引用；未确认不上传；取消、超限、断线、恢复和重试不误发、不重复扣费；Rust、JSON、Markdown 代码块可读且可复制。

### G4：发布门与渐进切换
G0–G3 的行为回归通过 Actions；真实浏览器完成普通聊天、搜索/URL/GitHub、附件三组流程；双账号隔离、设备离线独立性、额度和工具幂等、回滚证据齐全。通过后只按测试账号小批切流，旧路径保留到对账完成。

最近 DSH UI flaky e2e 修复的 [GitHub Actions](https://github.com/lilyco-42/deepseek-harness/actions) 已通过；这只证明对应测试修复，不代表 G0–G4 已完成或已部署。

## 放行后再做

- P1：本人设备上的 CLI/MCP（目录白名单、写操作确认、撤销）；手机适配；统一积分账本、管理员赠送、充值/消费/退款幂等与用量核对。匿名试用需先有服务端限额和反滥用。
- P2：私有 Pin 知识空间（普通用户 5 GB、会员 20 GB）、并发配额和删除回收；Tauri 复用 Web 授权；邮件连接器先只读或草稿。
- P3：自动代发 QQ/微信/Telegram、公开算力出租、多 Agent/ZeroStack 委派、重型编译器包，等有明确需求和成本证据再立项。
