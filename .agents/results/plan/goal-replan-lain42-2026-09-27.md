# Lain42 全平台 Agent：活动 Goal 重规划（2026-09-27）

本计划按用户能完成的任务定义成功，取代此前“先迁移 DSH、再补产品流程”的执行顺序。架构边界见[平台架构建议](../architecture/architecture-recommendation-lain42-platform.md)，机器任务清单见[计划 JSON](goal-replan-lain42-2026-09-27.json)。活动 Goal 继续进行中；本文不是线上完成声明。

## 目标

把 Lain42 做成打开网页或手机就能使用的 Agent：默认使用网站模型；搜索、URL、GitHub OAuth 和用户确认的附件能把真实资料交给模型并得到有来源的回答；免登录用户有受限试用，登录用户的数据和凭据严格隔离；客户端承担合适的解析与代码展示；只有用户明确授权后才在其本人设备运行 CLI/MCP；积分、模型用量和私有知识空间可审计、可对账。

成功由用户结果决定，不由采用哪个框架决定。DSH 是优先评估的对话运行时，只有通过身份隔离、真实任务、错误恢复和资源门槛后才接生产流量。每轮只有一个执行者，不双推理、不双扣费、不重复运行有副作用的工具。

## 六项完成门

1. **打开即用**：桌面和手机的 Web/PWA 可用网站模型；匿名试用有服务端额度与反滥用限制，不获得私人凭据、设备或持久私有数据。设备离线不影响普通聊天。
2. **真正干活**：搜索、公开 URL、GitHub OAuth 和附件结果进入当前轮模型；回答当前问题并给出可打开来源。工具完成通知不算答案。
3. **授权隔离**：网站 OAuth 与设备本机 gh 独立；撤销立即生效；令牌不进入模型或普通日志；会话、文件、设备、知识、积分和用量不跨账号。
4. **本人设备按需运行**：只有用户选中并授权自己的设备后才运行 CLI/MCP；设备、目录、权限、写操作确认和撤销可见。A7A 永远是站点所有者的私人设备。
5. **客户端计算**：代码高亮、文件预览和有界解析优先在浏览器/Worker；用户确认实际发送内容。按实测选择 JS、Worker 或 WASM，不绕过 CORS 或系统权限。
6. **商业运营**：充值、消费、退款、管理员发放和模型用量形成幂等可审计账本；普通用户 5 GB、会员 20 GB 私有知识空间由服务端强制配额并正确回收。

全目标完成须同时具备 Actions、真实浏览器、双账号隔离、手机主要流程、设备断线、费用/配额幂等及回滚证据。编译成功、OAuth 卡片显示连接或工具显示完成都不单独算通过。

## 执行顺序

| 阶段 | 交付 | 放行标准 |
|---|---|---|
| G0 可信对话 | 修复错答、串题、失败回合污染；区分模型限流、站点容量和设备离线 | 真实模型多轮、短追问、纠正和错误恢复回归通过 |
| G1 身份与 turn 契约 | 服务端推导身份、受限匿名会话、turnId/requestId、事件顺序、取消/续读和用量关联 | 双账号跨读拒绝；匿名不能访问私人资源；请求幂等 |
| G2 资料到答案 | 搜索、URL、GitHub OAuth 真实读取后交给同轮模型 | 真实回答、来源和工具记录可按同一轮追踪；撤销生效 |
| G3 附件、代码与手机 | 客户端预览/确认/解析，Rust/JSON/Markdown 高亮，窄屏操作 | 合成附件被准确引用；未确认不上传；失败可恢复且不重复计费 |
| G4 积分与知识 | 可审计账本、管理员发放、usage 对账、私有 OSS 和 5/20 GB 配额 | 重复交易幂等；并发上传不超额；跨账号不可读；删除释放配额 |
| G5 本人设备工具 | 用户本人设备上的 CLI/MCP，能力白名单、目录限制、写入确认、撤销 | 仅 owner 可执行；设备离线不影响 G0–G4；不依赖 A7A |
| G6 运行时与发布 | 受保护入口比较现有循环与 DSH，之后渐进切流 | DSH 通过同一安全、功能、恢复、资源和回滚门才切换；不通过就保留基线，不阻塞产品流程 |

G0 和 turn 契约可并行；身份隔离是私人 OAuth/文件/设备开放前置。G2 和 G3 基于 turn 契约推进。G4 依赖身份和用量关联；G5 依赖身份、授权和审计。DSH 只在隐藏入口试跑，生产默认路径最后切换。

## 工作包与接口原则

- 先复现普通聊天的错答、短输入串题、失败轮污染、429/503 和容量拒绝。失败说明真实类别，不用硬编码答案冒充模型。
- 浏览器不提交可信 userId、workspaceId、cwd 或模型密钥。每轮有 requestId、turnId、runId 与单调事件序号；事件可续读，副作用不自动重放。
- 搜索、WebFetch、GitHub OAuth 和附件必须先取得真实资料，再交给同轮模型继续回答。GitHub 网站 OAuth 不依赖本机 gh。
- 附件先在客户端展示解析范围、片段和大小，用户确认后才发送；大文件可取消且有资源上限。
- 积分复用现有钱包/权益真值，禁止无来源直接改余额。知识 OSS 对象私有，服务端事务维护配额预留、删除和恢复。
- 若 DSH 试点继续，New API 通过内网与短时、限定受众和能力的身份断言调用；不能公开 DSH Host/Remote 管理入口或通用 shell/filesystem preset。

## 不做

本轮不共享 A7A、不做公共算力出租、自动代发邮件/QQ/微信/Telegram、多 Agent 委派、全站 Rust/WASM 重写或重型 LLVM 包。ZeroStack 只保留为未来可选 coding worker。

## 当前证据

- New API 是线上 Agent 基线；DSH PeerScope 不等同网站用户授权，通用 Web preset 含 shell/filesystem 能力，不能直接公网开放。
- 最新已知 New API 提交 11b65a2 修复容量错误提示；Actions CI 36276903522 和 Linux Agent 构建 36276903498 通过。该版本尚未部署；公开状态曾报告 agent-4f9032e。提示修复不会释放服务器磁盘。
- 目前没有六项能力通过同一套 Actions 与真实浏览器验收的证据，活动 Goal 继续进行中。

## 固定约束

- 项目构建、自动化测试和打包只在 GitHub Actions；本机不编译或运行项目测试。
- Actions 未通过不部署；部署后核对服务版本和浏览器流程。
- 不重启或共享 A7A，不读取浏览器 Cookies，不把 OAuth/API key 交给模型。
- 完成记录包含代码版本、Actions run、部署版本、浏览器结果和限制；未部署或未实测的功能明确标注。
