# Lain42 Agent：当前执行看板

本看板落实 [目标与验收计划](./lain42-agent-goal-2026-09-26.md)；它是执行排序，不表示未验证能力已经完成。

## 北极星目标

用户打开手机或浏览器即可用网站模型聊天；搜索、公开 URL、GitHub OAuth 和用户确认的附件都必须把真实资料交给当前轮模型并生成可核验回答。普通流程不依赖任何个人设备，所有私有数据按账号隔离。

## 当前发布门：P0 全部通过前不扩功能

| 顺序 | 工作项 | 完成证据 | 状态 |
|---|---|---|---|
| P0-A | 对话连贯与错误恢复：问候、短追问、纠正、工具失败后的新问题；设备离线时普通聊天仍可用 | 多模型/重复 Actions 回归 + 真实浏览器多轮流程；检查延迟长尾 | 进行中：纠正场景语义通过一次，耗时偏长 |
| P0-B | 搜索、URL、GitHub OAuth 的实际资料进入同一轮模型 | 每类工具都验证实际输入、模型回答、可打开来源；OAuth 用测试账号验证仓库读取，不要求本机 gh | 部分通过：公开搜索与 URL 有单场景证据；OAuth 未验收 |
| P0-C | 附件从预览、确认到模型分析闭环 | 使用合成文件验证预览范围、用户确认、模型引用文件内容、取消和重试；未确认不得发送 | 未验收 |
| P0-D | 双账号隔离：会话、OAuth、附件、设备、知识数据和用量 | 两个测试账号互相访问均被拒绝；撤销授权后立即失效；Actions 自动化通过 | 未验收 |
| P0-E | 设备离线独立性与端到端放行 | 关闭所有个人设备后，普通聊天、公开搜索、网站 OAuth 仍成功；CI 通过并完成浏览器验收 | 初步通过：A7A 离线时聊天可用；其余需纳入完整回归 |

P0-A 到 P0-D 必须在 P0-E 放行前完成。CI 是必要条件，不能替代真实浏览器结果；任一项失败就留在当前发布门，不宣布完成。

## 放行后的顺序

| 阶段 | 工作项 | 完成证据 |
|---|---|---|
| P1 | 本人设备上的 CLI/MCP | 仅设备所有者可调用；写操作确认；撤销与断线状态可验证；设备离线不影响 P0 流程 |
| P1 | 积分和商业账本 | 充值、管理员赠送、预留、消费、退款可审计；重复回调幂等；能与模型用量对账 |
| P1 | 手机与客户端代码体验 | 手机完成聊天、上传、取消、重连和来源查看；Rust/JSON/Markdown 展示与复制通过浏览器回归 |
| P2 | Pin 私有知识空间 | 普通用户 5 GB、会员 20 GB；并发上传不超额，删除释放配额，跨账号不可读 |
| P2 | 桌面入口与额外连接器 | Tauri 复用 Web 会话与授权；新消息连接器先只读/草稿，发送单独授权 |

## 固定架构边界

- Web/PWA 是统一用户入口；Tauri 后续复用同一产品流程。
- 目标架构由 DSH 统一管理对话与工具循环，New API 负责模型路由，Lain42 负责身份、授权、账本和数据所有权；迁移必须渐进、可回滚，并先证明多用户隔离。
- 浏览器 JS/Worker/WASM 负责适合本地的解析与展示；WASM 不绕过 CORS，也不替代操作系统 CLI。
- GitHub 网站 OAuth 与用户本人设备上的 `gh` 是两条独立授权路径。
- A7A 始终是站点所有者的私人设备，不作为共享 worker；它离线不能影响普通用户体验。
- ZeroStack、额外工具卡片、Rust/WASM 重写、公开设备出租都不能替代 P0 用户流程验收。
- 所有项目构建和自动化测试只通过 GitHub Actions 运行；Actions 未通过不部署。真实账号验收使用专用测试账号与合成数据，不把私有资料发给模型做演示。

## 当前已知证据

- 普通对话的上一轮纠正已有一次线上语义通过记录，但响应偏慢，未达到整体门槛。
- 公开 URL 与公开搜索各有一次线上资料回流模型并带来源的记录，仍需纳入回归。
- GitHub OAuth 卡片显示已连接不算完成；OAuth 读取内容并由模型回答尚未验收。
- 附件 UI 与本地预览路径存在，但完整的“确认发送→模型引用文件内容”尚未验收。
- 双账号数据隔离尚无完整的自动化和浏览器证据。

## 执行规则

先补齐 P0 发布门并修复其阻塞点；不新开 P1/P2 功能来掩盖 P0 未通过。每次变更先由 GitHub Actions 验证，再进行目标浏览器流程验收并记录证据。只有所有 P0 项均有可复查证据时，才切换默认入口并开始下一阶段。
